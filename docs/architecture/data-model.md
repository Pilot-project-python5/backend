# 개념 데이터 모델

이 문서는 기능 간 데이터 책임을 설명한다. 논리 엔티티와 관계는 docs/architecture/erd.md를 기준으로 하며 실제 컬럼과 제약은 Feature Packet과 마이그레이션에서 확정한다.

## 회원과 인증

- User(사용자): 로그인 아이디, 정규화 값, 이메일, 이메일 정규화 값, 비밀번호 해시, 인증 상태
- HealthProfile(건강 프로필): 생년월일, 성별, 키, 몸무게
- EmailVerification(이메일 인증): 사용자별 발급 이력, HMAC 인증번호 해시, 만료,
  재전송 가능 시각, 실패 횟수, 사용·대체 시각
- RefreshSession(리프레시 세션): 사용자, 고유 HMAC 토큰 해시, 만료·폐기·마지막 사용·
  생성 시각. 사용자 삭제 시 함께 삭제하며 사용자·생성 시각과 만료 시각으로 조회한다.
  회전은 해시와 마지막 사용 시각을 바꾸고 로그아웃·재사용 탐지는 폐기 시각을 남긴다.
- F-1.4 access 인증은 JWT의 사용자·세션 식별자를 User·HealthProfile·RefreshSession과
  읽기 비교한다. 별도 access token 테이블 없이 세션 폐기와 고정 만료를 즉시 반영한다.

## 카탈로그

- ProductCategory(제품 카테고리): 고유 slug, 표시 이름, 활성 여부, 정렬 순서. F-2.2에서
  실제 테이블과 기준 시드를 추가했으며 `all`·`전체`는 DB 행이 아닌 API 가상 항목이다.
- Product(제품): 영양제 또는 의약품 유형, 고유 SKU, 브랜드, 이름, 로컬 또는 CDN 이미지
  URL, 단위 형태, 총 용량, 원화 표시 가격, 게시·편집 순서. F-2.3에서 실제 테이블과
  활성 카테고리 다대다 매핑·결정적 제품 시드를 추가한다.
- Nutrient(영양성분): 고유 code, 이름, 기준 단위와 활성 여부. F-2.4에서 실제 기준
  테이블·결정적 시드를 추가하며 참조 중에는 물리 삭제하지 않고 비활성화한다.
- ProductNutrient(제품 영양성분): 제품과 성분의 다대다 연결, 단위당 Decimal 함량,
  단위와 제품별 표시 순서. F-2.4에서 실제 테이블을 추가하고 제품 삭제 시 연결만
  함께 삭제한다.
- ExpertComment(전문가 코멘트): 제품별 저자 표시 문자열, 일반 텍스트 추천 이유,
  활성 여부와 편집 순서. F-2.4.1에서 실제 테이블·결정적 시드를 추가하고 상세에서만
  활성 항목을 제공한다.
- PurchaseLink(구매 링크): 제품별 판매처 표시·HTTPS 절대 URL, 활성 여부와 편집 순서.
  F-2.4.2에서 실제 테이블·결정적 개발 시드를 추가하고 제품 삭제 시 함께 삭제한다.

## 마이케어

- CareItem(복용 항목): F-3.1에서 실제 구현한 사용자·카탈로그 제품 연결, 구매일,
  복용 시작일, 총수량, 회당 복용량과 하루 횟수. 사용자 삭제 시 함께 삭제하고 참조
  중인 제품 삭제는 제한한다. 같은 제품의 반복 등록은 별도 행으로 보존한다.
- CareNutrientSnapshot(복용 성분 스냅샷): F-3.2에서 실제 구현한 CareItem 등록
  시점의 활성 영양성분 ID·이름·단위당 함량·단위. 영양제에만 생성하며 등록 후
  카탈로그 변경과 분리된 불변 계산 입력이다. CareItem 삭제 시 함께 삭제하고 참조
  중인 Nutrient 삭제는 제한한다.
- CareHistory 또는 상태 이력: 소진과 사용 중단의 추적

F-3.1 care_items는 생성 이력의 최소 필드만 가진다. F-3.2는 기존 등록 API 내부에서
care_nutrient_snapshots를 함께 저장한다. 재구매와 재고 의미는 F-3.3,
상태·소진 예정일은 F-3.7 이후, 유통기한은 F-3.11의
Feature Packet과 마이그레이션에서 확장한다.

## 알림

- Notification(알림): 사용자, CareItem, 종류, 기준일, 예약 시각, 화면 읽음 상태
- EmailDelivery(이메일 발송): Notification, 수신 주소, 상태, 시도 횟수, 마지막 오류

## 기준 데이터

- 영양소 기준 CSV: 나이 범위, 성별, 성분, 기준량, 단위, 출처와 버전

CSV는 적재 전에 필수 열, 나이 구간 중복, 단위와 키 중복을 검증한다.
