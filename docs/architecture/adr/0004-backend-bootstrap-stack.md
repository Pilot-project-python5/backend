# ADR-0004 백엔드 부트스트랩 기술 구성

- 상태: accepted
- 날짜: 2026-08-10

## 배경

1차 MVP는 AWS와 운영 외부 서비스 없이 로컬에서 재현되어야 하며 프론트엔드와
후속 AI 개발자는 Swagger 계약을 사용한다. 개발·테스트 PostgreSQL을 분리하고
기능 단위 SDD 검증을 자동화할 실행 기반이 필요하다.

## 결정

- Python 3.12와 FastAPI를 사용한다.
- Python 의존성과 실행은 uv 및 저장소의 uv.lock으로 고정한다.
- PostgreSQL 16, SQLAlchemy 2 동기 세션과 psycopg 3를 사용한다.
- 모든 스키마 변경은 Alembic 마이그레이션으로 수행한다.
- Docker Compose는 API, 작업자, 개발 DB, 테스트 DB와 Mailpit을 실행한다.
- API와 작업자는 같은 이미지에서 별도 프로세스로 실행한다.
- 개발 DB는 볼륨에 보존하고 테스트 DB는 tmpfs로 격리한다.
- 공통 요청 ID와 오류 응답을 부트스트랩부터 적용한다.

## 근거

- 동기 SQLAlchemy 세션은 1차 MVP의 데이터 흐름을 단순하게 유지한다.
- psycopg 3 연결 문자열을 명시해 드라이버 선택 차이를 제거한다.
- uv.lock과 컨테이너를 함께 사용해 호스트 Python과 패키지 버전 차이를 줄인다.
- API와 작업자 코드를 공유하되 프로세스를 분리하면 2차 스케줄러 전환 시 도메인
  코드를 바꾸지 않고 실행 어댑터를 교체할 수 있다.

## 결과

- 기능 모델과 테이블은 승인된 Feature Packet에서만 추가한다.
- 부트스트랩 마이그레이션은 제품 테이블이 없는 기준점만 만든다.
- 제품·의약품과 영양소 시드는 해당 기능 승인 전까지 등록하지 않는다.
- 전체 완료 검증에는 Docker와 PostgreSQL이 필요하다.
