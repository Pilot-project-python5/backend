# 테스트 전략

테스트는 pytest 표식으로 `unit`, `contract`, `integration`을 구분한다. 기능 테스트는
`@pytest.mark.feature("F-x.y")`로 Feature Packet과 연결하고 `make feature-check`로
대상 기능만 검증한다.

## 단위 테스트

- 생년월일 기반 나이 계산
- 영양소 단위 변환과 합산
- 마지막 복용 예정일과 상태 전환
- 유통기한 상태 전환
- 알림 대상일 D-5, D-3, D-1
- 인증번호 만료, 재전송과 실패 제한

## 통합 테스트

- PostgreSQL 제약과 저장소
- 회원과 건강 프로필 트랜잭션
- 성분 스냅샷 보존
- 소유권 검증
- 알림과 이메일 발송 상태의 멱등성
- 마이그레이션과 시드 재실행

## 계약 테스트

- 생성된 OpenAPI
- 요청·응답 예시
- 공통 오류 응답 형식
- 쿠키 인증
- 상태 코드와 enum
- 데이터 변경 시 ERD, ORM 모델과 마이그레이션 제약의 일치

## 인수 테스트

Feature Packet의 모든 인수 조건 ID를 테스트 이름 또는 표식과 연결한다.

데이터 변경 기능은 ERD 변경 또는 변경 없음의 근거, 빈 DB 마이그레이션과 기존 스키마 업그레이드 결과를 함께 남긴다.

## 결정적 가짜 구현

- FakeClock으로 날짜와 오전 9시 경계를 고정한다.
- FakeEmailSender로 수신자, 제목, 본문과 발송 횟수를 검증한다.
- 외부 구매 링크는 네트워크 호출 없이 이동 계약만 검증한다.

## 부트스트랩 검사

- 생존 확인은 PostgreSQL 없이 성공한다.
- 준비 확인은 PostgreSQL 연결 실패를 공통 오류 계약으로 반환한다.
- 알 수 없는 경로도 공통 오류 계약을 사용한다.
- 개발·테스트 DB 이름과 연결을 분리한다.
- 저장소 openapi.json과 실행 중 FastAPI 계약이 일치한다.
- 빈 DB 기준 마이그레이션과 시드를 두 번 실행해도 성공한다.

## 핵심 시나리오

- 이메일 미인증 로그인 거부
- 인증번호 10분 만료와 5회 실패
- DB 시드에 없는 제품 등록 거부
- 영양제만 영양소 합계에 포함
- D-day 다음 날 DEPLETED
- D-5부터 LOW_STOCK
- D-5, D-3, D-1 이외 날짜에는 알림 없음
- 동일 알림 작업자 재실행 시 중복 없음
- 새 복용 항목이 기존 소진 이력을 덮어쓰지 않음
