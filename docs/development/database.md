# 로컬 데이터베이스

논리 데이터 기준은 docs/architecture/erd.md다. 실제 컬럼과 제약은 승인된 Feature Packet과 마이그레이션에서 확정하며 데이터 변경 PR은 ERD를 같은 변경에서 갱신한다.

## 데이터베이스 엔진

1차부터 PostgreSQL 16을 사용한다. SQLite로 대체하지 않는다. 애플리케이션은
SQLAlchemy 2 동기 세션과 psycopg 3 드라이버를 사용하고 연결 문자열은 환경변수로
주입한다.

권장 논리 DB:

- allyakkkuk_dev
- allyakkkuk_test

실제 이름과 자격증명은 환경변수로 관리하며 Git에 저장하지 않는다.

## 마이그레이션 규칙

- 모든 스키마 변경은 마이그레이션으로 수행한다.
- 신규 SQLAlchemy 모델 모듈은 src/allyakkkuk/db/models.py에 등록한다.
- 데이터 변경 전에 Feature Packet에 ERD 영향, 관계, 제약, 인덱스와 이력 정책을 기록한다.
- 엔티티·관계·제약 변경은 docs/architecture/erd.md와 같은 PR에서 갱신한다.
- 빈 DB에서 최신 상태까지 적용 가능해야 한다.
- 컬럼 삭제, 타입 축소와 대량 갱신은 별도 호환성 계획이 필요하다.
- 데이터 보존에 영향을 주는 downgrade는 사용자 승인 없이 실행하지 않는다.
- 마이그레이션과 애플리케이션 코드의 배포 순서를 Feature Packet에 기록한다.
- 외부 ERD 페이지가 아니라 저장소 ERD를 구현 기준으로 사용한다.

## 테스트 격리

- 개발 DB와 테스트 DB를 공유하지 않는다.
- 테스트는 트랜잭션 롤백 또는 격리된 스키마로 상태를 초기화한다.
- 병렬 실행을 도입할 때 테스트 간 식별자 충돌을 방지한다.
- 테스트 DB 이름은 `_test`로 끝나야 하며 통합 테스트가 이를 확인한다.
