# 1차 로컬 MVP 완료 점검

## 결론

2026-08-14 기준 백엔드 담당 1차 기능은 모두 구현되어 `main`에 병합됐다. 프론트엔드는
Swagger와 openapi.json을 계약으로 개발할 수 있고, AWS·운영 이메일·외부 AI 없이
Docker Compose에서 API, PostgreSQL, Mailpit과 알림 worker를 재현할 수 있다.

이 문서는 로컬 MVP의 기능 완료를 의미하며 운영 배포 준비 완료를 의미하지 않는다.

## 최종 검증 근거

- `make verify`: 466개 테스트 통과, 총 커버리지 95.07%
- ruff format/check와 mypy: 242개 소스 파일 통과
- Alembic: 테스트 PostgreSQL에서 0020 head까지 적용하고 ORM 차이 없음 확인
- 시드: 7세트 84건을 연속 2회 적용해 멱등성 확인
- ERD: 19개 필수 엔티티와 20개 관계 검증 통과
- OpenAPI: 생성 결과와 `openapi.json` 일치
- F-3.12 기능 검사: 관련 테스트 12개 통과

최종 검증은 F-3.12 PR #25의 병합 대상과 같은 코드에서 수행했고, 문서 마감 변경을
포함한 브랜치에서도 `make verify`를 다시 실행해 같은 결과를 확인했다.

## 로컬 인수 절차

1. `.env.example`을 `.env.local`로 복사한다.
2. `make dev`, `make migrate`, `make seed`를 실행한다.
3. Swagger `http://localhost:8000/docs`와 Mailpit `http://localhost:8025`를 확인한다.
4. `make verify`로 코드·마이그레이션·시드·ERD·OpenAPI와 전체 테스트를 검증한다.

세부 명령과 예상 결과는 `docs/development/local-setup.md`와
`docs/development/commands.md`를 따른다.

## 2차 인계 경계

- AWS 실행 환경, 운영 PostgreSQL, 비밀정보 관리, 이미지 저장소·CDN
- 관리형 작업 스케줄러·큐, 다중 인스턴스 관측성과 장애 재처리
- 운영 이메일 공급자, 제공자 멱등 키 또는 transactional outbox, 반송·스팸 처리
- 개인정보·알림·전달 이력 보관 기간과 물리 정리 정책
- 다른 개발자가 연결할 AI 코칭 F-4 전체와 의료 안전·근거 추적
- 운영 부하·보안 시험, 백업·복구, 모니터링·경보와 배포 자동화

2차 구현은 기존 ports와 도메인 경계를 유지하고, 공개 API 변경 시 OpenAPI와 프론트엔드
영향을 같은 PR에 기록한다.

## 알려진 로컬 MVP 제약

- worker가 트리거 날짜 내내 중단되면 지난 D-day 알림을 다음 날 소급 생성하지 않는다.
- 로컬 SMTP가 메일을 수락한 직후 SENT 저장 전 프로세스가 종료되면 중복 가능성이 있다.
- 실제 복용 여부·잔량 보정, 복용 계획 수정, 삭제 복원과 운영자 재처리는 제공하지 않는다.
- 영양성분 현황은 등록된 보충제 복용 계획과 공인 기준량의 비교이며 진단·처방이 아니다.
