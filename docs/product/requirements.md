# 저장소 요구사항 기준

이 문서는 영양꾹 백엔드의 기능 명세·구현·검증에 사용하는 로컬 요구사항 원본이다. 외부 문서 서비스에 접속하지 않고도 작업할 수 있도록 확정된 제품 정책을 보관한다.

## 문서 권위와 변경 규칙

- 이 문서와 승인된 Feature Packet을 구현 권위로 사용한다.
- 기능 ID, 단계, 담당과 상태는 docs/features/manifest.yaml에서 관리한다.
- 기능 하나의 상세 API·데이터·인수 조건은 해당 Feature Packet에서 확정한다.
- 사용자 결정이 바뀌면 코드보다 이 문서와 관련 Feature Packet을 먼저 갱신한다.
- 외부 링크는 docs/source-map.md에 출처 이력으로만 보관한다.

## FR-1 회원과 인증

### 회원가입

- 이름, 로그인 아이디, 비밀번호, 비밀번호 확인, 이메일, 생년월일, 성별, 키와 몸무게를 입력한다.
- 숫자 나이는 저장하지 않고 생년월일과 계산 기준일로 계산한다.
- 로그인 아이디는 정규화 후 고유하게 관리한다.
- 비밀번호 원문을 저장하거나 로그에 남기지 않는다.
- 이메일 인증 전에는 로그인을 허용하지 않는다.

### 이메일 인증

- 6자리 인증번호를 이메일로 전송한다.
- 인증번호 유효시간은 10분이다.
- 재전송 대기시간은 60초다.
- 최대 5회 실패 제한을 적용한다.
- 인증번호 원문 대신 검증 가능한 해시를 저장한다.
- 1차에서는 로컬 SMTP 수신함과 가짜 이메일 발신기로 검증한다.

### 로그인과 세션

- 아이디와 비밀번호로 로그인한다.
- 인증 실패는 아이디 또는 비밀번호 중 어떤 값이 틀렸는지 노출하지 않는다.
- 액세스·리프레시 토큰은 HttpOnly 쿠키로 전달한다.
- 액세스 토큰 수명은 15분, 리프레시 토큰 수명은 14일이다.
- 쿠키는 SameSite=Lax를 사용하고 로컬에서는 Secure=false, 배포 환경에서는
  Secure=true로 설정한다.
- 로그인 성공마다 리프레시 세션을 새로 만들어 기기별 다중 로그인을 허용하고,
  리프레시 토큰 원문 대신 해시만 저장한다.
- 인증 갱신마다 리프레시 토큰을 회전하고 이전 토큰 재사용 시 해당 세션을 폐기한다.
- 리프레시 세션 만료는 최초 로그인부터 14일로 고정하며 갱신으로 연장하지 않는다.
- 로그아웃은 현재 리프레시 세션만 폐기하고 반복 호출할 수 있다.
- access JWT와 서버 리프레시 세션을 함께 검증해 로그아웃·세션 만료·계정 정지를
  보호 API에 즉시 반영한다.
- 현재 사용자 기본·건강 프로필과 access·refresh 만료 시각을 조회하고, access 만료
  뒤에는 명시적인 인증 갱신 또는 로그인 흐름을 제공한다.

## FR-2 전문가 큐레이션

- 전체, 비타민, 단백질, 오메가3 등의 활성 제품 카테고리를 제공한다.
- `전체`는 DB 카테고리가 아니라 필터 미적용을 뜻하는 가상 `all` 항목이며 항상
  첫 번째다. 실제 활성 카테고리는 sort_order와 slug로 안정적으로 정렬한다.
- 게시 상태인 추천 제품만 목록에 노출한다.
- 추천 제품 목록은 비회원 공개 API이며 category를 생략하거나 `all`로 보내면 전체,
  활성 category slug를 보내면 해당 분류만 조회한다. 알 수 없거나 비활성인 유효 slug는
  404로 구분한다.
- 목록은 편집 sort_order와 sku로 안정적으로 정렬하고 1부터 시작하는 page와
  1~100 범위 page_size, total과 has_next를 제공한다.
- 제품 이미지 URL, 카테고리, 브랜드, 제품명, 표시 가격, 구성 성분과 총 용량을 제공한다.
- 목록 카드 미리보기와 단일 제품의 패키지·성분 상세를 분리하며, 전문가 코멘트와
  외부 구매 연결은 각각 F-2.4.1과 F-2.4.2에서 독립적으로 확장한다.
- 단일 상세는 제품 UUID로 공개 조회하며 목록 공통 필드, 패키지 형태·총 단위 수와
  활성 구성 성분·단위당 함량을 제공한다. 공개 조건을 만족하지 않는 제품은 404로
  통일하고 성분이 없으면 빈 배열을 제공한다.
- 패키지 수량과 단위당 함량은 Decimal 정밀도를 보존하는 JSON 문자열로 제공하며
  1차 성분 단위는 MG, G, MCG, IU를 사용한다.
- 제품별 전문가 코멘트와 추천 이유를 제공한다.
- 전문가 코멘트는 제품 상세의 `expert_comments` 배열로 제공하고 활성 항목만 제품별
  편집 순서로 정렬한다. 목록은 가볍게 유지하며 코멘트 토글을 열 때 상세를 조회한다.
- 코멘트가 없으면 빈 배열을 반환하고, 코멘트 내용은 HTML·Markdown이 아닌 일반
  문자열로 취급한다.
- 활성 외부 구매 링크로 이동할 수 있게 한다.
- 외부 구매 이동은 공개 제품 UUID의 별도 GET 경로에서 첫 활성 링크를 선택해 307로
  응답한다. 공개 제품이 아니면 404로 숨기고 링크가 없으면 별도 404로 구분한다.
- 구매 URL은 HTTPS 절대 URL만 허용하고 응답은 캐시와 referrer 전달을 막는다.
- 1차 MVP에서는 외부 링크 클릭 이력과 사용자 추적 데이터를 수집하지 않는다.
- 서비스 내부 구매, 결제, 주문과 배송은 제공하지 않는다.
- 제품, 의약품, 성분, 코멘트와 구매 링크는 DB 시드로 관리한다.
- 전문가 소개는 1차에서 프론트엔드 정적 콘텐츠로 관리한다.
- 추천 소식 알림 F-2.5는 2차로 연기한다.

## FR-3 마이케어

### 복용 제품 등록

- 로그인 회원만 사용할 수 있다.
- DB 카탈로그에 존재하는 영양제와 의약품만 등록할 수 있다.
- 구매일과 별도 복용 시작일을 저장한다.
- 총 보유 수량, 회당 복용량과 하루 복용 횟수를 저장한다.
- 총 보유 수량은 해당 구매 항목의 최초 구매 총량이며 제품의 정·캡슐·스쿱·포
  단위를 등록 시점 스냅샷으로 함께 보존한다.
- 카탈로그에 없는 제품을 사용자가 직접 입력하지 않는다.
- 재등록은 기존 소진 기록을 덮어쓰지 않고 새 복용 항목으로 보존한다.
- 동일 제품의 미소진 재고가 남아 있어도 재구매 수량을 합산하지 않는다.
- 복용 항목 삭제는 `deleted_at`을 기록하는 이력 보존형 소프트 삭제로 처리한다.
- 삭제된 복용 항목과 성분 스냅샷은 보존하되 활성 목록과 후속 계산·알림 대상에서는
  제외한다.

### 성분과 예정 섭취량

- 영양제 등록 시 제품의 구성 성분과 단위당 함량을 복용 항목의 스냅샷으로 보존한다.
- 카탈로그가 바뀌어도 기존 복용 항목의 계산 결과가 달라지지 않아야 한다.
- 일일 예정 섭취량은 단위당 함량 × 회당 복용량 × 하루 복용 횟수로 계산한다.
- 동일 성분은 변환 가능한 기준 단위로 맞춰 합산한다.
- G·MG·MCG는 영양성분의 기준 단위로 정확히 상호 변환하고 IU는 IU끼리만 합산한다.
  IU와 질량 단위 사이의 성분별 환산은 1차 일일 예정 섭취량에서 지원하지 않는다.
- 일일 예정 섭취량은 특정 날짜의 실제 복용량이 아니라 삭제되지 않은 활성 복용
  계획의 하루 총량이므로 미래 복용 시작 계획도 포함한다.
- 계산 결과는 저장하지 않고 활성 복용 항목과 등록 시점 성분 스냅샷으로 요청마다
  계산한다.
- 실제 복용 기록은 1차 범위에 포함하지 않는다.
- 의약품은 복용 목록, 재고와 유통기한 관리에는 포함하지만 영양소 합계에서는 제외한다.

### 의약품 카탈로그

- 의약품은 게시된 MEDICATION Product와 1:1 상세가 모두 있는 DB 시드만 목록·상세 API에
  노출하고 사용자가 직접 생성·수정하지 않는다.
- 1차 분류는 일반의약품 OTC와 전문의약품 PRESCRIPTION을 사용한다.
- 품목 추적 코드, 유효성분 요약, 효능, 용법·용량, 주의사항, 보관법, 출처명·HTTPS URL과
  출처 검토일을 상세 필수 정보로 보존한다.
- 로컬 1차 시드는 실제 복약 지시가 아닌 API·UI 검증용임을 명시하고, 운영 데이터로
  전환할 때 품목별 공식 출처 검토를 필수로 한다.

### 영양소 기준 데이터

- 계산 시점의 나이와 성별에 맞는 기준량을 사용한다.
- 원본은 애플리케이션 코드와 분리된 CSV로 관리한다.
- 적재 전에 필수 열, 단위, 중복 키와 겹치는 나이 구간을 검증한다.
- 출처와 버전을 추적할 수 있어야 한다.
- 1차 기준은 보건복지부·한국영양학회의 2025 한국인 영양소 섭취기준을 사용한다.
- 개인 비교는 권장섭취량(RNI)을 우선하고, 권장섭취량이 없으면 충분섭취량(AI)을
  사용한다. 임신·수유 추가량은 1차 회원 프로필로 판별할 수 없어 제외한다.
- 일반 OMEGA_3는 EPA+DHA와 동일하다고 보장할 수 없어 기준량을 임의 매핑하지 않는다.
- 기준량이 없는 성분·나이도 현재 보충제 예정량은 제공하고 기준량과 비율은 제공하지
  않는다.
- 달성 비율은 보충제 예정량이 총 식이 기준량에서 차지하는 비율이며 100%를 초과해도
  자르지 않는다. 식사 섭취량이나 임상적 결핍·과잉 판정으로 사용하지 않는다.

### 예상 소진일과 재고 상태

- 예상 소진일은 `복용 시작일 + ceil(총수량 / (회당 복용량 × 하루 횟수)) - 1일`로
  계산하고 나누어떨어지지 않는 잔여량도 마지막 부분 복용일 하루로 센다.
- 예상 소진일은 CareItem에 저장하고 기존 행도 같은 공식으로 백필한다.
- D-day 정수는 예상 소진일과 APP_TIMEZONE 조회일의 차이로 매번 계산하며 저장하지 않는다.
- 소진 D-5부터 LOW_STOCK 상태다.
- D-day 다음 날부터 DEPLETED 상태다.
- 새 복용 항목 등록은 기존 소진 이력을 덮어쓰지 않는다.

### 유통기한

- 재고 상태와 유통기한 상태를 분리한다.
- 유통기한은 구매분별 CareItem 선택 값이며 등록 시 생략할 수 있고 보호된 갱신 API로
  추가·교정한다. 없으면 날짜·D-day·상태는 null이며 알림 대상에서 제외한다.
- 유통기한 상태는 NORMAL, EXPIRING_SOON, EXPIRED를 사용한다.
- APP_TIMEZONE 오늘 기준 D-6 이상은 NORMAL, D-5부터 당일까지 EXPIRING_SOON,
  다음 날부터 EXPIRED다. 상태와 D-day는 저장하지 않고 조회 시 계산한다.
- 수량이 남아 있어도 유통기한이 지나면 EXPIRED가 될 수 있다.

### 화면 알림과 이메일

- 재구매와 유통기한 알림을 화면 내부와 이메일로 모두 제공한다.
- 알림은 D-5, D-3, D-1의 APP_TIMEZONE(기본 Asia/Seoul) 오전 9시에만 생성한다.
- 논리 이벤트는 대상 복용 항목, 알림 종류, 기준일과 트리거 날짜 기준으로 중복을
  방지하고 화면·이메일 채널이 공유한다. 채널별 전달 상태는 후속 전달 엔티티에서
  별도로 중복을 방지한다.
- 작업자를 같은 날짜에 다시 실행해도 중복 생성하거나 발송하지 않는다.
- 화면 알림은 현재 사용자별 최신순 페이지와 개별 멱등 읽음 처리를 제공하며 1차
  MVP에서는 기간 제한 없이 보관한다.
- 이메일은 당일 논리 이벤트와 ACTIVE·인증 사용자를 대상으로 Mailpit에 전달한다.
  Notification별 수신 주소·상태·시도 횟수·재시도 시각·성공 시각·안전 오류 코드를
  보존하고 최초 포함 최대 3회, 실패마다 5분 간격으로 재시도한다.

## FR-4 AI 코칭

- AI 코칭 전체는 1차 MVP 범위에서 제외한다.
- 2차에서 다른 개발자가 안정된 조회 계약을 통해 연결한다.
- AI 모듈은 auth, catalog와 care 테이블을 직접 수정하지 않는다.
- 의료 진단과 처방을 생성하지 않으며 필요한 최소 건강정보만 사용한다.

## 1차 로컬 실행 요구사항

- FastAPI와 PostgreSQL 개발·테스트 DB를 사용한다.
- SQLite로 대체하지 않는다.
- 로컬 이메일 수신함과 로컬 알림 작업자를 사용한다.
- 마이그레이션은 빈 DB에서 재현 가능해야 한다.
- 시드는 반복 적재 가능하고 실제 개인정보·건강정보를 포함하지 않아야 한다.
- Swagger와 생성된 OpenAPI가 실제 요청·응답과 일치해야 한다.
- 단위, 통합, 계약과 인수 테스트를 제공한다.
- AWS 계정, 운영 이메일 공급자와 외부 AI 없이 전체 검증이 가능해야 한다.

## 1차 제외 범위

- AWS 또는 운영 서버 배포
- 운영 이메일 공급자
- 추천 소식 알림
- AI 코칭과 외부 LLM
- 의약품·영양제 상호작용 분석
- 실제 복용 여부 기록
- 카탈로그에 없는 제품 직접 입력
- 운영자 화면
- 서비스 내부 결제, 주문과 배송

## 1차 확정 정책과 운영 전 재검토

- 이메일 주소는 소문자 정규화 값으로 계정 전체에서 고유하다.
- 1차는 복용 계획·수량 수정과 유통기한 제거 API를 제공하지 않는다.
- 삭제된 복용 항목은 소프트 삭제 상태로 보존한다. 복원·물리 정리와 이력 보존 기간은
  운영 전 개인정보 정책과 함께 확정한다.
- 영양소 기준은 `2025 한국인 영양소 섭취기준` CSV와 F-3.6의 열·단위·변환·버전·
  checksum 검증 계약을 따른다.
- 로컬 이메일은 Mailpit, 최초 포함 최대 3회·고정 5분 재시도를 사용한다. 운영 공급자와
  제공자 멱등 키 또는 outbox는 2차에서 확정한다.
