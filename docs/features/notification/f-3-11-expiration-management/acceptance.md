# F-3.11 인수 조건

## AC-F-3.11-001 선택 등록과 미관리 상태

전제: 유통기한을 아는 구매분과 모르는 구매분이 있다.

행동: 각각 복용 항목으로 등록하고 목록을 조회한다.

결과: 입력 날짜는 보존되고 생략 항목은 날짜·D-day·상태가 모두 null이다.

## AC-F-3.11-002 상태 날짜 경계

전제: 같은 유통기한에 대해 KST 오늘이 D-6·D-5·D0·다음 날이다.

행동: 목록을 조회한다.

결과: 상태는 NORMAL·EXPIRING_SOON·EXPIRING_SOON·EXPIRED이고 D-day는 6·5·0·-1이다.

## AC-F-3.11-003 소유 활성 항목 갱신

전제: 현재 사용자·다른 사용자·삭제·없는 항목이 있다.

행동: PUT으로 유통기한을 생성 또는 교정한다.

결과: 현재 사용자 활성 항목만 갱신되고 같은 날짜 재요청은 같은 200 결과이며 나머지는
404 CARE_ITEM_NOT_FOUND다.

## AC-F-3.11-004 재고 상태와 독립

전제: 예상 소진일까지 시간이 남았지만 유통기한은 지난 항목이 있다.

행동: 목록을 조회한다.

결과: days_until_depletion은 양수여도 expiration_status는 EXPIRED다.

## AC-F-3.11-005 마이그레이션과 장애

전제: 기존 CareItem과 0017 스키마, 저장소 장애가 있다.

행동: 0018 upgrade·downgrade와 API를 실행한다.

결과: 기존 행은 null로 보존되고 열·인덱스가 ORM·ERD와 일치하며 장애는 503이다.

## 유효성 및 실패 사례

- 유효하지 않은 ISO 날짜·UUID는 422이고 과거 날짜는 허용한다.
- 인증 없음은 401이며 다른 사용자·삭제 항목의 존재 여부를 구분해 노출하지 않는다.

## 데이터·ERD 인수 조건

- 0018의 nullable DATE와 `(expiration_date, user_id)` 인덱스가 ORM·ERD와 일치한다.
