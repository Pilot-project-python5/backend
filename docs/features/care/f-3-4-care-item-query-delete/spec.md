# F-3.4 복용 제품 조회·삭제

## 목표

로그인 사용자가 자신이 등록한 현재 활성 영양제·의약품 구매 항목을 최신 등록순으로
조회하고, 더 이상 관리하지 않을 항목을 목록에서 제거한다. 삭제 뒤에도 구매·성분
스냅샷과 향후 상태·알림의 근거를 보존할 수 있도록 이력 보존형 삭제를 권장한다.

## 사용자 이야기

사용자로서, 현재 관리 중인 복용 제품과 각 독립 구매분을 확인하고 불필요한 항목을
제거하기 위해 내 복용 항목 목록을 조회하고 삭제하고 싶다.

## 비즈니스 규칙

1. 목록 조회와 삭제는 유효한 access JWT와 서버 refresh session을 가진 로그인
   사용자만 사용할 수 있다.
2. 목록에는 현재 사용자 소유이면서 `deleted_at IS NULL`인 영양제·의약품 CareItem만
   포함한다. 다른 사용자의 항목은 절대 포함하지 않는다.
3. 동일 제품의 재구매분은 합산하지 않고 각각 독립 항목으로 반환한다.
4. 목록은 `created_at DESC, id DESC` 최신 등록순으로 안정 정렬한다.
5. 페이지는 1부터 시작하고 기본 page_size는 20, 허용 범위는 1~100이다. 빈 페이지도
   200과 빈 items, 정확한 total·has_next를 반환한다.
6. 각 항목은 CareItem의 구매·복용·수량 스냅샷과 현재 Product의 유형·브랜드·이름·
   이미지 표시 정보를 제공한다. 게시되지 않은 제품도 이미 등록된 사용자 항목이면
   조회한다.
7. 영양성분 스냅샷은 F-3.5 계산용 내부 데이터로 유지하고 F-3.4 응답에는 포함하지
   않는다.
8. 삭제는 물리 삭제가 아니라 서버 현재 시각을 `deleted_at`과 `updated_at`에
   기록하는 소프트 삭제다. CareItem과 성분 스냅샷 행은 보존한다.
9. 현재 사용자의 활성 항목만 삭제할 수 있다. 없거나, 다른 사용자 소유이거나, 이미
   삭제된 항목은 모두 404 `CARE_ITEM_NOT_FOUND`로 통일한다.
10. 삭제 성공은 본문 없는 204다. 반복 삭제는 첫 요청 이후 404를 반환한다.
11. 목록·삭제 성공 응답은 개인 건강 관련 데이터 캐시를 막기 위해 `Cache-Control:
    no-store`를 포함한다.
12. DB 조회·갱신 실패는 503 `SERVICE_UNAVAILABLE`로 변환하고 부분 상태 변경을 남기지
    않는다.

## 포함 범위

- 사용자 소유 활성 CareItem 페이지 목록 조회
- CareItem별 현재 제품 표시 정보와 등록 시점 구매·복용·수량 정보 제공
- 최신 등록순 안정 정렬과 page·page_size·total·has_next
- 사용자 소유 활성 항목의 소프트 삭제와 204 응답
- 다른 사용자·미존재·기삭제 항목의 동일 404 처리
- `deleted_at` ORM·0014 마이그레이션·부분 인덱스·ERD
- 단위·계약·통합·인수·마이그레이션 테스트와 OpenAPI 문서

## 제외 범위

- 단일 항목 상세 조회 API
- 복용 계획·구매 수량 수정과 삭제 복원
- 삭제 항목 목록·휴지통·보존 기간 만료 후 물리 정리
- 영양성분 스냅샷의 외부 조회
- 실제 잔량, 일일 섭취량, 소진일, 재고·유통기한 상태와 알림 계산
- 제품명·이미지 등 카탈로그 표시 정보의 구매 시점 스냅샷
- AWS·AI 연결

## 시나리오

### 기본 흐름

- 사용자는 목록을 요청해 자신이 등록한 활성 CareItem을 최신순 페이지로 받는다.
- 같은 제품을 두 번 등록했다면 서로 다른 ID·구매일·수량을 가진 두 항목으로 받는다.
- 사용자가 자신의 활성 항목을 삭제하면 204를 받고 다음 목록에서 제외된다.
- 삭제 뒤에도 CareItem과 F-3.2 성분 스냅샷은 DB에 남는다.

### 실패와 경계

- 인증하지 않은 목록·삭제 요청은 401 `AUTH_REQUIRED`다.
- page가 1 미만이거나 page_size가 1~100 밖이면 422 `VALIDATION_FAILED`다.
- 다른 사용자 ID, 존재하지 않는 ID와 이미 삭제된 ID의 삭제는 모두 같은 404다.
- 빈 목록과 전체 개수를 넘는 페이지는 200과 빈 items를 반환한다.
- 카탈로그 제품이 비게시 상태로 바뀌어도 사용자 활성 CareItem 목록에서는 숨기지 않는다.
- DB 실패는 503이며 삭제 시각을 부분 기록하지 않는다.
