# F-3.1 인수 조건

## AC-F-3.1-001 복용 제품 등록

전제: 사용자가 로그인했고 DB에 영양제 또는 의약품 카탈로그가 있다.

행동: 제품 ID, 구매일, 복용 시작일, 총수량, 1회 복용량과 일일 횟수를 제출한다.

결과: 현재 사용자가 소유한 새 복용 항목을 저장하고 등록 값을 201로 반환한다.

## AC-F-3.1-002 인증과 소유권

- 인증 쿠키가 없거나 유효하지 않으면 401 `AUTH_REQUIRED`다.
- 요청은 user_id를 받지 않고 인증된 사용자 ID만 저장한다.
- 다른 사용자가 같은 제품을 등록하면 서로 다른 소유 항목이 된다.

## AC-F-3.1-003 카탈로그 경계

- DB에 존재하는 영양제·의약품은 게시 여부와 무관하게 등록할 수 있다.
- DB에 없는 제품 ID는 404 `PRODUCT_NOT_FOUND`다.
- 제품명을 직접 입력하는 계약은 없다.

## AC-F-3.1-004 날짜 검증

- 구매일이 서버 기준 오늘 이후면 422 `VALIDATION_FAILED`다.
- 복용 시작일이 구매일보다 빠르면 422 `VALIDATION_FAILED`다.
- 구매일 이후의 미래 복용 시작일은 예약 등록으로 허용한다.

## AC-F-3.1-005 수량과 횟수 검증

- 총수량과 1회 복용량은 0 초과, NUMERIC(12,3) 범위여야 한다.
- 1회 복용량은 총수량을 초과할 수 없다.
- 일일 복용 횟수는 1~24다.
- 위반 요청은 422 `VALIDATION_FAILED`다.

## AC-F-3.1-006 반복 등록과 장애

- 같은 요청을 두 번 보내면 서로 다른 ID의 두 항목을 생성한다.
- PostgreSQL 저장 실패는 세부정보 없는 503 `SERVICE_UNAVAILABLE`다.

## AC-F-3.1-007 데이터·ERD 일치

- care_items의 필드·FK·CHECK·인덱스·삭제 정책이 모델·0011 마이그레이션·ERD와
  일치한다.
- 0011 upgrade와 0010 downgrade 후 다시 upgrade할 수 있다.

## 비기능 경계

- 실제 개인정보·건강정보·비밀정보를 시드나 로그에 포함하지 않는다.
- AWS·AI·이메일·스케줄러 없이 로컬 PostgreSQL에서 검증할 수 있다.
