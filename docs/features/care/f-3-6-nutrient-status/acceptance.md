# F-3.6 인수 조건

## AC-F-3.6-001 나이·성별 기준 현황

전제: 서로 다른 생년월일·성별의 로그인 사용자와 2025 KDRI 기준 CSV가 적재되어 있다.

행동: 각 사용자가 영양성분 현황을 조회한다.

결과: 서버 기준일의 만 나이·성별에 맞는 RNI 또는 AI가 선택되고 현재 예정량,
기준량, 단위, 기준 유형과 비율이 반환된다.

## AC-F-3.6-002 F-3.5 경계와 비율 의미

전제: 현재 사용자에게 영양제·의약품·삭제 항목·미래 시작 영양제와 100%를 넘는
보충제 예정량이 함께 있다.

행동: 영양성분 현황을 조회한다.

결과: F-3.5와 같이 활성 영양제 계획만 계산하되 미래 시작 계획을 포함하고 의약품과
삭제 항목을 제외한다. 비율은 100%를 넘겨 반환하며 실제 식사 또는 임상 판정이 아님을
API 설명에서 확인할 수 있다.

## AC-F-3.6-003 기준 없음과 빈 결과

전제: 한 사용자는 일반 OMEGA_3처럼 정확히 매핑할 기준이 없는 성분을 복용하고 다른
사용자는 활성 영양제 성분이 없다.

행동: 각 사용자가 현황을 조회한다.

결과: 첫 사용자는 현재량과 reference_available=false 및 null 기준 필드를 받고,
두 번째 사용자는 기준 메타데이터와 빈 nutrients 배열을 200으로 받는다.

## AC-F-3.6-004 생일 경계와 결정적 정렬

전제: FakeClock 기준으로 오늘이 생일인 사용자와 내일이 생일인 사용자가 있고 여러
성분 코드가 역순으로 저장되어 있다.

행동: 현황을 조회한다.

결과: 지난 생일 기준 만 나이가 정확하고 결과는 nutrient_code·nutrient_id 순이다.

## AC-F-3.6-005 인증·장애·캐시

전제: 인증 없음, DB 장애, 설정한 기준 버전 없음과 정상 요청을 각각 준비한다.

행동: 현황을 조회한다.

결과: 인증 없음은 401 AUTH_REQUIRED, 저장소·기준 버전·변환 오류는 부분 결과 없는
503 SERVICE_UNAVAILABLE이며 정상 200에는 Cache-Control: no-store가 있다.

## AC-F-3.6-006 CSV 검증과 멱등 적재

전제: 정상 CSV와 필수 열 누락·잘못된 단위·중복 키·겹치는 나이 구간·불일치 메타데이터
CSV를 준비한다.

행동: 기준 시드를 적용하고 같은 정상 시드를 반복 적용한다.

결과: 비정상 CSV는 DB 변경 전에 거부하고 정상 CSV는 버전·checksum·값을 원자적으로
적재하며 반복 실행 후 행과 값이 같다.

## AC-F-3.6-007 데이터·ERD 일치

전제: 빈 PostgreSQL과 0014 스키마가 있다.

행동: 0015 upgrade·downgrade와 ORM·ERD 검사를 수행한다.

결과: 두 기준 테이블의 관계·CHECK·UNIQUE·인덱스가 일치하고 downgrade는 기존 사용자·
카탈로그·CareItem 데이터를 보존한다.
