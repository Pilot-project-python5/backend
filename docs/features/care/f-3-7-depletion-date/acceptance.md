# F-3.7 인수 조건

## AC-F-3.7-001 정확히 나누어지는 예상 소진일

전제: 8월 1일 시작, 총 60정, 1회 1정, 하루 2회 계획이 있다.

행동: 항목을 등록하고 조회한다.

결과: 필요 일수 30일, 예상 소진일 8월 30일이 등록·목록 응답에 같다.

## AC-F-3.7-002 마지막 부분 복용일

전제: 총 10개, 하루 사용량 3개인 계획이 있다.

행동: 예상 소진일을 계산한다.

결과: 올림한 4일을 사용하고 시작일 포함 네 번째 날을 소진일로 반환한다.

## AC-F-3.7-003 D-day 날짜 경계

전제: 같은 예상 소진일에 대해 주입한 KST 조회일을 3일 전·당일·다음 날로 바꾼다.

행동: 활성 목록을 조회한다.

결과: days_until_depletion은 각각 3·0·-1이며 저장하지 않는다.

## AC-F-3.7-004 소유권·삭제·오류

전제: 현재 사용자·다른 사용자·삭제 항목과 인증 없음·DB 실패가 있다.

행동: 목록을 조회한다.

결과: 현재 사용자의 활성 항목만 날짜를 받고 인증 없음은 401, DB 실패는 503이다.

## AC-F-3.7-005 기존 행 백필과 롤백

전제: 0015 스키마에 여러 수량·복용 계획의 기존 CareItem이 있다.

행동: 0016 upgrade·downgrade를 수행한다.

결과: 기존 행은 서비스와 같은 올림 공식으로 백필되고 CHECK·NOT NULL·인덱스가
ORM·ERD와 일치하며 downgrade 후 기존 행은 보존된다.

## 유효성 및 실패 사례

- 기존 Pydantic·서비스·DB 양수 규칙이 0 총수량·0 복용량·0 횟수를 계속 거부한다.

## 데이터·ERD 인수 조건

- 0016의 열·백필·CHECK·NOT NULL·인덱스가 ORM과 docs/architecture/erd.md에 일치한다.
