# F-1.1.1 아이디 중복 확인

## 목표

회원가입 전에 입력한 로그인 아이디를 사용할 수 있는지 확인해 사용자가 가입 요청
단계에서 중복 오류를 미리 해결할 수 있게 한다.

## 사용자 이야기

신규 사용자로서, 가입을 완료하기 전에 원하는 로그인 아이디의 사용 가능 여부를
확인하고 싶다.

## 비즈니스 규칙

1. 로그인 아이디는 회원가입과 동일하게 영문자·숫자 5~20자만 허용한다.
2. 로그인 아이디를 소문자 정규화한 값으로 조회하며 대소문자를 구분하지 않는다.
3. 같은 정규화 로그인 아이디가 어떤 상태의 사용자에게든 존재하면 사용할 수 없다.
4. 유효한 조회는 존재 여부와 관계없이 200과 available 불리언을 반환한다.
5. 조회 결과는 아이디를 예약하지 않으며 최종 고유성은 회원가입의 DB UNIQUE 제약이
   보장한다.
6. 잘못된 로그인 아이디 형식은 422 VALIDATION_FAILED로 거부한다.
7. PostgreSQL 조회 실패는 내부 정보를 노출하지 않고 503 SERVICE_UNAVAILABLE로
   변환한다.

## 포함 범위

- 공개 로그인 아이디 사용 가능 여부 조회 API
- 회원가입과 동일한 로그인 아이디 형식 검증과 정규화
- 사용자 상태와 무관한 중복 판정
- 요청·응답·오류 예시를 포함한 Swagger/OpenAPI 계약

## 제외 범위

- 로그인 아이디 예약 또는 선점
- 회원가입 수행과 사용자 정보 반환
- 이메일 중복 확인과 가입 정보 전체 검증
- 공개 조회 속도 제한과 봇 방지
- 테이블, 인덱스, 마이그레이션과 시드 변경

## 시나리오

### 기본 흐름

- 사용자가 유효하고 존재하지 않는 아이디를 조회하면 available=true를 확인한다.
- 사용자가 기존 아이디와 대소문자만 다른 값을 조회하면 available=false를 확인한다.

### 실패와 경계

- 5자 미만, 20자 초과 또는 영문자·숫자 외 문자가 포함된 값은 422다.
- 같은 아이디를 반복 조회해도 데이터를 변경하지 않고 같은 결과를 반환한다.
- DB 조회가 실패하면 503을 반환하며 SQL과 사용자 정보를 노출하지 않는다.
- 조회 직후 다른 가입 요청이 먼저 성공할 수 있으므로 실제 가입에서는 UNIQUE 제약을
  다시 적용한다.
