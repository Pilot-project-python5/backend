# F-1.1.3 이메일 인증

## 목표

가입 직후 이메일 미인증 사용자가 로컬 메일함으로 받은 6자리 코드를 확인해 계정을
활성화할 수 있게 한다.

## 사용자 이야기

신규 사용자로서, 가입 응답의 사용자 ID로 인증번호를 발급받아 이메일 소유를 확인하고
로그인 가능한 ACTIVE 상태가 되고 싶다.

## 비즈니스 규칙

1. 발급·재전송·확인은 가입 응답의 user_id 또는 발급 응답의 verification_id로
   대상을 식별하며 로그인 세션을 요구하지 않는다.
2. 인증번호는 숫자 6자리이고 10분간 유효하다. expires_at과 같은 시각부터 만료다.
3. 인증번호 원문은 응답·로그·DB에 저장하지 않고, 발급 ID와 서버 비밀값을 사용한
   HMAC-SHA256 결과만 저장한다.
4. 같은 사용자의 새 코드는 직전 발급의 resend_available_at 이상인 시각부터 만들 수
   있다. 60초 전 재요청은 429다.
5. 새 코드 발급 시 사용되지 않은 이전 코드를 superseded 처리해 즉시 무효화하고 실패
   횟수는 새 행에서 0으로 시작한다.
6. 잘못된 코드 입력은 해당 발급 건의 failed_attempts를 증가시킨다. 1~4번째는 400,
   5번째와 이후 시도는 429이며 해당 코드는 잠긴다.
7. 잠긴 코드도 발급 후 60초가 지나면 새 코드로 재전송할 수 있다.
8. 유효한 코드를 확인하면 해당 발급 건을 used 처리하고 사용자를 ACTIVE로 바꾸며
   email_verified_at과 updated_at을 같은 현재 시각으로 기록한다.
9. 이미 ACTIVE이거나 email_verified_at이 있는 사용자의 발급·재전송은 409다.
10. PENDING_EMAIL_VERIFICATION이 아닌 정지 계정은 발급·재전송할 수 없다.
11. 존재하지 않는 사용자 또는 발급 ID는 404이며, 만료는 410, 이미 사용되었거나 새
    코드로 대체된 발급 건은 409다.
12. PostgreSQL 또는 메일 발송 실패는 503으로 변환한다. 메일 발송이 실패한 발급은
    트랜잭션을 롤백해 사용 가능한 코드로 남기지 않는다.

## 포함 범위

- 최초 인증번호 발급, 60초 이후 재전송, 인증번호 확인 공개 API
- email_verifications 이력 테이블과 사용자 활성화 트랜잭션
- 교체 가능한 코드 생성기·해시기·Clock·EmailSender 경계
- Mailpit 로컬 SMTP 발송과 테스트용 fake sender
- Swagger/OpenAPI 요청·응답·오류 예시

## 제외 범위

- 이메일 링크 방식 인증, 비밀번호 재설정, 이메일 주소 변경
- 인증 전 사용자의 재가입·삭제·정리 정책
- IP·계정 단위 속도 제한, CAPTCHA와 운영 악용 방지
- AWS·운영 이메일 공급자, 재시도 큐와 transactional outbox
- 로그인·세션 토큰 발급

## 미결 질문

- 없음. 2026-08-11에 사용자가 user_id 기반 분리 API, 5회 잠금, 60초 뒤 재발급,
  성공 시 ACTIVE 전환, 이미 인증된 사용자 409 정책을 승인했다.
