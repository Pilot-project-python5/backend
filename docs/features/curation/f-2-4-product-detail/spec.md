# F-2.4 추천 제품 정보

## 목표

방문자가 추천 제품 카드에서 제품별 패키지 수량과 구성 성분·단위당 함량을 정확히
확인할 수 있게 한다. 목록 응답은 가볍게 유지하고 계산에 쓰일 소수 값은 정밀도를
잃지 않는 계약으로 제공한다.

## 사용자 이야기

방문자로서, 추천 제품이 어떤 형태로 몇 단위 들어 있고 한 단위에 어떤 성분이 얼마나
포함되는지 판단하기 위해 단일 제품 상세 정보를 조회하고 싶다.

## 비즈니스 규칙

1. `GET /api/v1/curation/products/{product_id}`는 인증 없이 호출할 수 있다.
2. `product_id`는 UUID이며 잘못된 형식은 공통 `422 VALIDATION_FAILED`로 응답한다.
3. 게시 상태이고 활성 카테고리 매핑이 하나 이상인 제품만 상세에 노출한다.
4. 유효한 UUID라도 미존재·비게시·활성 카테고리 연결 없음은 모두
   `404 PRODUCT_NOT_FOUND`로 동일하게 응답한다.
5. 상세는 F-2.3 목록 필드에 `package`와 `nutrients`를 추가한다.
6. `package`는 패키지 단위 코드와 0보다 큰 총 단위 수를 제공한다.
7. `nutrients`는 활성 성분만 제품별 `sort_order`, 성분 code 순으로 제공한다.
8. 성분이 없는 공개 제품은 오류가 아니라 빈 `nutrients` 배열을 반환한다.
9. 총 단위 수와 단위당 함량은 JSON Decimal 문자열로 직렬화한다.
10. 1차 허용 성분 단위는 `MG`, `G`, `MCG`, `IU`다.
11. DB 읽기 실패는 내부 정보를 숨기고 공통 `503 SERVICE_UNAVAILABLE`로 응답한다.
12. 성분 시드는 code 자연 키와 제품 SKU를 사용해 반복 실행해도 승인 값으로 수렴한다.

## 포함 범위

- 공개 단일 추천 제품 상세 API
- 목록 공통 필드와 활성 카테고리 slug
- 패키지 형태와 총 단위 수
- nutrients·product_nutrients ORM, 마이그레이션, ERD
- 활성 구성 성분과 단위당 함량
- UI 시안 제품 3종의 결정적 성분 시드
- 단위·통합·계약·인수 테스트와 OpenAPI 문서

## 제외 범위

- 전문가 코멘트(F-2.4.1)
- 외부 구매 링크와 이동(F-2.4.2)
- 의약품 효능·복용법·주의·보관 상세(F-3.10)
- 영양소 기준량, 단위 변환과 사용자 섭취 합산(F-3 계열)
- 관리자 CRUD, 실제 판매가 연동, 이미지 업로드
- AWS·운영 CDN, 추천 소식과 AI 연결

## 시나리오

### 기본 흐름

- 방문자가 F-2.3 목록의 제품 id로 상세 API를 호출한다.
- 서비스가 제품 공개 조건을 확인하고 활성 카테고리와 활성 성분을 조회한다.
- 목록 공통 정보, 패키지와 정렬된 성분을 하나의 응답으로 반환한다.
- 영양 성분이 없는 공개 제품은 빈 배열을 받아 상세 화면을 정상 표시한다.

### 실패와 경계

- UUID가 아니면 422를 반환한다.
- 존재하지 않거나 공개 조건을 만족하지 않는 제품은 정보 노출 없이 같은 404를 반환한다.
- 비활성 성분은 응답에서 제외한다.
- DB 장애는 503으로 변환하고 SQL·연결 정보를 응답에 포함하지 않는다.
- 시드를 두 번 실행해도 성분·제품 매핑 수와 승인 값이 변하지 않는다.
