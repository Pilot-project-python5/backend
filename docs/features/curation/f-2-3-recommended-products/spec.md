# F-2.3 추천 제품 목록

## 목표

프론트엔드가 전체 또는 활성 카테고리 slug로 게시된 전문가 추천 제품을 안정적인
편집 순서와 페이지 정보로 조회하고 제품 카드 미리보기를 표시할 수 있게 한다.

## 사용자 이야기

방문자로서, 원하는 카테고리를 선택해 현재 게시 중인 추천 제품만 살펴보고 제품의
기본 정보와 가격을 비교하고 싶다.

## 비즈니스 규칙

1. GET /api/v1/curation/products는 로그인 없이 호출하는 공개 읽기 API다.
2. category를 생략하거나 `all`로 보내면 활성 카테고리가 하나 이상 연결된 모든 게시
   제품을 조회한다.
3. 실제 category slug는 활성 product_categories에 존재해야 하며 해당 카테고리와
   연결된 게시 제품만 조회한다.
4. 형식은 유효하지만 존재하지 않거나 비활성인 category는 404 CATEGORY_NOT_FOUND다.
   slug 형식 자체가 잘못되면 422다.
5. 같은 제품이 여러 카테고리에 연결돼도 응답에는 한 번만 나타난다.
6. 제품은 sort_order 오름차순, 동순위면 sku 오름차순으로 안정적으로 정렬한다.
7. page는 1부터 시작하고 기본값 1이다. page_size는 기본 20이며 1~100만 허용한다.
8. 응답은 items, page, page_size, total, has_next를 포함한다. 범위를 벗어난 빈 페이지도
   200과 빈 items를 반환한다.
9. 목록 항목은 id, sku, product_type, brand, name, image_url, display_price, currency와
   활성 category_slugs만 반환한다. currency는 1차에서 KRW 고정이다.
10. products는 SUPPLEMENT 또는 MEDICATION 유형이며 게시 제품만 공개한다. 활성
    카테고리 연결이 없는 제품은 전체 목록에서도 공개하지 않는다.
11. display_price와 sort_order는 0 이상, units_per_package는 0보다 크며 sku는 대문자
    영문·숫자와 내부 하이픈 형식으로 고유하다.
12. 로컬 제품 이미지는 DB의 `/static/products/...` 경로로 관리하고 백엔드가 실제
    정적 파일을 제공한다. 2차 CDN URL도 같은 image_url 계약으로 교체한다.
13. 민재코치 승인 제품 32종을 고정 SKU 기준으로 멱등 upsert하고 카테고리 매핑을
    승인 상태로 복원한다.
14. 원본에 없는 가격은 0으로 유지한다. 2026-08-18에 원본에서 확인한 제품별 사진은
    최대 1200px WebP로 정규화하고 메타데이터를 제거한 로컬 정적 파일로 보관한다.
    실행 시 외부 이미지 URL에 의존하지 않는다.
15. 이전 카탈로그에서 제외된 제품은 복용 이력 참조 보존을 위해 삭제하지 않고
    비공개 처리한다.
16. DB 조회 실패는 내부 상세를 숨기고 503 SERVICE_UNAVAILABLE로 응답한다.

## 포함 범위

- products와 product_category_mappings ORM·PostgreSQL 마이그레이션
- 게시·정렬·가격·패키지 정보 제약과 목록 조회 인덱스
- 카테고리 필터·페이지네이션이 있는 공개 추천 제품 목록 API
- 제품별 로컬 WebP 정적 이미지 제공
- 제품 32종과 카테고리 매핑 결정적 시드
- 단위·통합·계약·인수 테스트, ERD와 Swagger/OpenAPI 문서

## 제외 범위

- 제품 구성 성분과 단위당 함량 상세(F-2.4)
- 전문가 코멘트(F-2.4.1)와 외부 구매 이동(F-2.4.2)
- 제품·카테고리 관리자 API와 사용자별 추천
- 실시간 가격 연동, 이미지 업로드, AWS 스토리지·CDN
- 서비스 내부 결제·주문·배송, 추천 소식과 AI

## 시나리오

### 기본 흐름

- 방문자가 category, page와 page_size로 추천 제품 목록을 요청한다.
- 서버는 실제 category이면 활성 여부를 먼저 확인한다.
- 저장소는 게시 제품과 활성 카테고리 매핑을 필터링하고 중복 없이 전체 건수와 현재
  페이지 제품을 안정된 순서로 읽는다.
- 서버는 카드 미리보기와 페이지 메타데이터를 반환한다.
- 프론트엔드는 image_url을 같은 로컬 백엔드 origin에서 읽고, 이후 product id로
  F-2.4 상세를 조회한다.

### 실패와 경계

- 비활성·비게시·활성 카테고리 연결이 없는 제품은 전체와 필터 결과에서 제외한다.
- 유효하지 않은 페이지 값과 slug 형식은 422, 알 수 없거나 비활성 slug는 404다.
- 제품이 없거나 마지막 페이지 뒤를 요청해도 정상 빈 페이지를 반환한다.
- 여러 카테고리 연결로 JOIN 행이 늘어도 제품과 total은 중복 계산하지 않는다.
- 시드를 여러 번 실행하거나 승인 값을 변경한 뒤 실행해도 제품·매핑이 중복되지 않고
  승인 상태로 수렴한다.
- DB 실패는 빈 목록으로 숨기지 않고 503을 반환한다.
