# F-2.4.1 전문가 코멘트

## 목표

방문자가 추천 제품의 상세 정보와 함께 제품별 추천 이유를 담은 활성 전문가 코멘트를
확인할 수 있게 한다. 토글을 열 때 상세를 조회하도록 목록 응답은 기존 크기와 계약을
유지한다.

## 사용자 이야기

방문자로서, 추천 제품을 선택할지 판단하기 위해 제품 정보와 함께 전문가가 작성한
추천 이유를 확인하고 싶다.

## 비즈니스 규칙

1. 기존 공개 `GET /api/v1/curation/products/{product_id}` 성공 응답에
   `expert_comments` 배열을 추가한다.
2. 목록 API에는 코멘트를 추가하지 않고 토글을 열 때 상세 API를 사용한다.
3. 공개 제품 판정과 404·422·503 오류 계약은 F-2.4와 동일하다.
4. 활성 코멘트만 `sort_order ASC, id ASC`로 안정 정렬한다.
5. 활성 코멘트가 없으면 오류가 아니라 빈 배열을 반환한다.
6. 응답 항목은 `id`, `author_label`, `content`다.
7. author_label은 trim 기준 1~100자, content는 1~2000자다.
8. 코멘트는 HTML·Markdown이 아닌 일반 문자열로 전송한다.
9. 제품 삭제 시 연결된 코멘트도 삭제한다.
10. 코멘트 시드는 고정 comment UUID와 product SKU를 사용해 반복 실행해도 승인
    문구·활성·순서로 수렴한다.

## 포함 범위

- 제품 상세 응답의 expert_comments 배열
- 활성 코멘트 필터와 안정 정렬
- expert_comments ORM·마이그레이션·ERD
- 민재코치 승인 제품 32종의 카테고리 안내·주의 코멘트 결정적 시드
- 단위·통합·계약·인수 테스트와 OpenAPI 문서

## 제외 범위

- F-2.3 제품 목록 응답의 코멘트 포함
- 외부 구매 이동(F-2.4.2)
- experts 테이블과 전문가 계정·프로필 관리
- 관리자 CRUD, 사용자 코멘트, 평가·좋아요
- 의료적 효능 보증, AWS·AI 연결

## 시나리오

### 기본 흐름

- 방문자가 목록에서 코멘트 토글을 열며 제품 상세를 요청한다.
- 상세 저장소가 공개 제품 정보, 활성 카테고리·성분과 활성 코멘트를 조회한다.
- 기존 상세 필드와 정렬된 expert_comments를 200으로 반환한다.

### 실패와 경계

- 코멘트가 없거나 모두 비활성이어도 제품 상세는 빈 배열로 성공한다.
- 비공개 제품과 잘못된 UUID·DB 장애는 기존 F-2.4 오류 계약을 유지한다.
- 시드를 두 번 실행해도 코멘트 수와 승인 문구·순서가 변하지 않는다.
