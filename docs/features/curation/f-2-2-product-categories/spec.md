# F-2.2 제품 카테고리

## 목표

프론트엔드가 전문가 큐레이션 제품을 분류할 때 사용할 공개 카테고리 목록을 안정된
slug와 표시 순서로 제공한다.

## 사용자 이야기

방문자로서, 전체·비타민·단백질·오메가3 카테고리를 정해진 순서로 확인하고 이후 추천
제품 목록을 원하는 분류로 필터링하고 싶다.

## 비즈니스 규칙

1. GET /api/v1/curation/categories는 로그인 없이 호출할 수 있는 공개 API다.
2. 요청 본문·쿼리 없이 200과 items 배열을 반환한다.
3. 각 항목은 이후 F-2.3 필터에 사용할 slug와 화면 표시용 name만 노출한다.
4. `all`·`전체`는 실제 상품 분류가 아닌 필터 미적용을 뜻하는 가상 항목이며 DB에
   저장하지 않고 응답의 첫 번째에 항상 한 번만 추가한다.
5. DB에서는 is_active=true인 카테고리만 조회한다.
6. 실제 카테고리는 sort_order 오름차순, 같은 값이면 slug 오름차순으로 정렬한다.
7. 활성 카테고리가 없어도 200과 `all` 항목 하나를 반환한다.
8. DB 조회 실패는 내부 상세를 숨기고 503 SERVICE_UNAVAILABLE로 응답한다.
9. slug는 소문자 영문·숫자와 내부 하이픈만 허용하고 1~50자에서 고유하다.
10. name은 좌우 공백을 제외한 1~50자, sort_order는 0 이상이다.
11. 1차 개발 시드는 vitamin·비타민, protein·단백질, omega-3·오메가3를 고정 UUID와
    slug 자연 키로 멱등 upsert하며 실행할 때마다 승인된 이름·활성·순서를 복원한다.

## 포함 범위

- product_categories SQLAlchemy 모델과 PostgreSQL 마이그레이션
- slug·name·활성·정렬 DB 제약과 활성 정렬 인덱스
- 비타민·단백질·오메가3 결정적 개발 시드
- 가상 all을 포함한 공개 카테고리 조회 API
- 단위·통합·계약·인수 테스트와 Swagger/OpenAPI 문서

## 제외 범위

- 제품·카테고리 다대다 연결과 카테고리별 제품 조회(F-2.3)
- 카테고리 생성·수정·비활성화 관리자 API
- `all`을 product_categories 행으로 저장하거나 제품과 연결하는 동작
- 다국어 카테고리 이름과 사용자별 카테고리
- 전문가 소개(F-2.1 프론트엔드), 추천 소식 알림(F-2.5 2차)

## 시나리오

### 기본 흐름

- 방문자가 카테고리 API를 호출한다.
- 서버는 활성 DB 카테고리를 정해진 순서로 읽는다.
- 서버는 가상 all을 맨 앞에 붙여 slug·name 배열을 반환한다.
- 프론트엔드는 slug를 F-2.3 제품 목록 필터 값으로 보관한다.

### 실패와 경계

- 비활성 카테고리와 DB에 잘못 추가된 all slug는 공개 목록에서 제외한다. all은
  애플리케이션이 만드는 가상 항목만 존재한다.
- sort_order가 같은 카테고리는 slug로 안정적으로 정렬한다.
- 활성 DB 행이 0개여도 all만 포함한 정상 응답이다.
- 시드를 여러 번 실행해도 slug별 행이 중복되지 않고 승인 상태로 수렴한다.
- DB 장애는 빈 목록으로 숨기지 않고 503으로 반환한다.
