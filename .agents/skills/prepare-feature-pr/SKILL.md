# 기능 PR 준비

주 기능 ID 하나만 포함하는 검토 가능한 PR 패키지를 준비한다.

## 작업 절차

1. AGENTS.md, 승인된 Feature Packet, 연결된 docs/history 문서와 .github/pull_request_template.md를 읽는다.
2. 브랜치 전체 변경 사항과 Git 상태를 확인한다.
3. 브랜치 이름이 feat/<feature-id>-<slug> 형식인지 확인한다.
4. 명세, 구현, 마이그레이션, ERD, 테스트와 API 문서가 하나의 수직 기능을 이루는지 확인한다.
5. verify-sdd-feature가 만든 근거를 재사용한다. 누락된 검사는 결과를 추측하지 말고 다시 실행한다.
6. 데이터 변경 시 docs/architecture/erd.md 갱신과 ERD 검증 근거를 확인한다.
7. 기능 이력 문서가 실제 구현과 일치하고 validate_history.py --strict를 통과하는지 확인한다.
8. 마이그레이션, 호환성 영향, 보안 영향과 롤백 고려 사항을 식별한다.
9. 저장소 템플릿으로 PR 본문을 작성한다.

## 범위 규칙

- PR 하나에는 주 기능 ID 하나만 사용한다.
- 의존 기능 ID는 완전히 구현했다고 주장하지 말고 의존성으로만 기록한다.
- 관련 없는 리팩터링, 일괄 포맷 변경, 불필요한 생성 산출물과 선언하지 않은 여러 기능을 거부한다.
- 1차 PR에 AWS 배포와 AI 구현을 포함하지 않는다.
- 구현 완료 기능에 history_path와 엄격 검증된 이력 문서가 없으면 PR 준비를 완료하지 않는다.
- 명령 실행 결과가 증명하지 않은 검사를 통과했다고 쓰지 않는다.

## 결과물

PR 제목, 브랜치 이름, 완성된 PR 본문, 검증 근거와 차단 요소를 반환한다. 외부 GitHub 작업은 별도의 명시적 요청이 있어야 수행한다.
